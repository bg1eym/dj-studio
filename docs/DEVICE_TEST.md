# 第一次上机（Mac + Mixxx）

**只有连 Mixxx 时（`DJSTUDIO_ENGINE=mixxx djstudio`）才需要这份文档。** 默认的内置引擎不碰 Mixxx，只要装了 node（`brew install node`）：
放进打碟谱 → 等进度条 → ▶ 开始演出。

这些在云端 / 模拟器里都无法验证，需要在真机上逐条确认。每一步做完把输出发给 Claude。

## 0. 安装并体检

按 README 安装后：

```bash
~/.venvs/djstudio/bin/djstudio doctor
```

预期：ffmpeg ✓、Mixxx 曲库 ✓、IAC 总线 ✓。「Mixxx 曲库目录」若报错，在 Mixxx 偏好设置 → 曲库里添加 `~/Music/DJStudio`。

## 1. 放进曲子和打碟谱（验收：RW2023 的 14 首 + 《CDW 技法实战 set 打碟谱》）

1. 网页首页：只把打碟谱 PDF 拖进去。应显示「正在电脑里按谱上的文件名找曲子…」，然后「14 / 14 首曲子已就位」，分析自动开始。
   - 要验证：macOS 第一次会弹「终端想访问『下载』（桌面 / 文稿）文件夹」，点允许；不允许的文件夹会被跳过，缺的曲子手动拖进来。
   - 曲子不在 下载 / 桌面 / 文稿 / 音乐 里：把整个文件夹拖进网页。
2. 一个进度条走完 6 步。中间会退出并重启 Mixxx（开启「启动时重新扫描」），再逐首静音装进 deck 让 Mixxx 分析。
   - 要验证：重启后托管曲库的歌是否进了 Mixxx 库；装载能否触发分析；分析结果是否写回库；网格校正（RW2023 预计 8 首）写库后 Mixxx 是否认。
3. 「可以演出了」之后看「高级 → 曲库」：每首应是「Mixxx ✓」，没有「网格存疑」。

## 2. 映射 + 真机探测

1. 「同步」或「准备」会把 `DJStudio.js` / `DJStudio.midi.xml` 部署到 Mixxx 的 controllers 目录。
2. 准备时会自动把 mixxx.cfg 里 IAC 总线的映射换成 DJ Studio（沿用原来 AgentMCP 用的设备）。若日志提示找不到 IAC 设备，就在 Mixxx → 偏好设置 → 控制器 → IAC 总线：映射选 **DJ Studio**，勾「启用」。右上角应显示「引擎在线 0.4.0」。
3. 往 deck1 拖一首已分析的歌（不播放），把播放位置拖到曲中，然后在「体检」页点**真机探测**（或 `djstudio probe`）。

Mixxx 的行为已经按 2.5.6 源码逐条核对过（见 [MIXXX_NOTES.md](MIXXX_NOTES.md)），探测在真机上再确认一遍：

| 检查 | 不通过时 |
|---|---|
| SysEx 双向（Python→引擎 需要 XML 里的 0xF0 绑定） | 映射没换成 DJ Studio / 不是 0.4.0；准备时会自动改 mixxx.cfg |
| CC 备用传输 | 仅备用 |
| EQ / 滤波 / 效果单元控件能写能读 | 效果单元里没放效果，或 Mixxx 版本不同 |
| `bpm` 控件可写 | 版本不同 |
| 网格解码（对照 Mixxx 自己的 `beat_distance`） | 把结果发给 Claude |
| 推子模式 = 加性、deck 朝向左/右 | 引擎 init 没跑 |

听感项（探测测不了）：推子居中时两边音量是否一样；echo / reverb 是否挂在对的 deck。

## 3. 第一次播放

1. 先做一套短 set（3 首、两段过渡）：Set 页新建，或把 Claude 生成的 JSON 粘贴进去。
2. 演出页 → 准备（约 1 分钟）→ ▶ 开始。
3. 要验证：
   - AutoDJ 装载：没有误播、推子归中、装载后身份核对通过；
   - 过渡：B 准时起播（日志「B 起播（晚了 x 拍）」应 < 0.1）、没有「相位校正」刷屏、没有「小节错位」；
   - EQ / 滤波 / 推子曲线听感；echo / reverb 是否挂在对的 deck；
   - 演出页的旋钮 / 推子 / 电平和 Mixxx 自己窗口里的一致（同一时刻对照看几次；网页读的是同一批控件）；
   - 主输出电平：长交接两首满音量叠加时不应长时间顶红（体检里 ReplayGain 应为「已开启」）；
   - 淡出停止。
4. 日志在 `~/DJStudio/logs/`，整份发给 Claude。

## 4. 故障注入（可选）

播放中退出 Mixxx：网页应在 2 秒内报「引擎失联」，conductor 停发命令，60 秒后报错停止。

## 假设表（模拟器 / 测试台验证不了，靠真机和耳朵）

| 假设 | 依据 | 怎么核对 |
|---|---|---|
| 谱上 EQ 钟点位 → dB：12 点 0、10 点 -6、9 点 -11、8 点 -18、7 点 -25 dB | 谱：「7 点＝全切（-25 dB）」「B LOW 给到一半」写 10 点；中间按幂曲线（`plan/convert.py` 的 `eq_db`） | 同一段过渡分别在 Prime 4+ 上照谱拧、和 Mixxx 自动跑，听低频交接的深浅；不对就改 `EQ_TAPER` |
| 谱上「推子 5」= Mixxx 推子 50%（-10 dB） | Mixxx 推子曲线（`ControlAudioTaperPot(-20, 0, 1)`）；Prime 4+ 的推子曲线没查到 | B 半推子进场时的音量和 Prime 4+ 比 |
| 谱上 Filter「左 / 右 N 点」= Mixxx QuickEffect 滤波旋钮同一位置 | 位置对位置；两边滤波器的截止频率曲线不同 | 听「左 9 点（切一半）」是否差不多 |
| Main FX Reverb Wet/Dry 1/3 = Mixxx 效果单元 2 的 mix 0.33 | 位置对位置；混响本身不同 | 听尾巴 |
| #06 Key Lock 关（音高 +0.8 半音） | Mixxx keylock 的延迟会让叠放出双击（测试台实测 17–29ms） | 觉得音高不能接受就把 set 的 keylock 打开，同时听过渡里有没有双击 |
| 自估网格的半拍检查（`kick_onset`）在真曲上不会把对的网格换到反拍 | 只在合成曲上测过（kick 音高往下扫 +6 ～ +8，反拍 bass +0.5 ～ +1，门槛差 2）；60 分钟 set 的 18 首没有音频 | 曲库页看每首的网格线是不是压在 kick 上，尤其 Overdrive、Sanctum、Stigma、Fourth Dimension、High Street、Pria；The Realm、Pria、Rave On Time 反拍上也有 kick，挪完以后看一眼是不是压在主 kick 上 |
| Mac 上 20 倍速录 MP3 读盘跟得上（录音里没有缺口） | Linux 4 核上 20 / 60 倍速 0 次；Mac 的 CoreAudio 解码速度没量过 | 录一次整套 set，看网页上是不是「20 倍速」录完（跟不上会自动放慢重录并说明）；听一遍录音有没有掉音 |
| Mixxx ReplayGain 开着 | Mixxx 默认开；关着时两首满音量叠加会削波 | 体检「ReplayGain」一项 |
| 按谱找曲子能读到「下载 / 桌面 / 文稿 / 音乐」 | macOS 的文件夹权限（TCC）：从终端启动时第一次会弹窗问；没核对过 App 方式启动 | 放进打碟谱后看「在电脑里找到 N 首」 |
| 自动更新、关旧服务在 Mac 上能用 | `git pull --ff-only`（需要能免密拉取）；`lsof -t -iTCP:8430 -sTCP:LISTEN` + `ps -ww`（macOS 自带）；只在 Linux 上测过 | 启动时终端里的「已更新到最新版本」「之前打开的 DJ Studio 还在运行，先关掉它」；右上角提交号和 GitHub 上一致 |
| 引擎按 44100 Hz 输出、MacBook 扬声器设备是 48000 Hz 时，系统（AUHAL）负责转换，不变调、不变速 | PortAudio 的 Mac 输出不改设备采样率，由 AUHAL 转换。CI（Apple 芯片构建机，虚拟声卡 48000 Hz）实测声卡取数据的速度 = 墙钟的 1.012 倍；不转换的话会是 1.088 倍 | 网页上的播放头和听到的 kick 对齐；`~/DJStudio/logs/` 里的引擎声音信息（device_rate、underruns） |
| 换输出设备：演出中插耳机 / 连 AirPods / 在菜单栏换输出，声音跟过去 | 引擎每 0.5 秒问 CoreAudio 的默认输出，换了就重开到新设备（Pa_Terminate + Pa_Initialize 刷新设备列表）；命令行程序没有 CFRunLoop，所以先把 kAudioHardwarePropertyRunLoop 设成 NULL，让 HAL 用自己的线程更新默认设备。CI 只测了「重开以后接着出声」，没法真的插耳机 | 演出中插 / 拔耳机、连 / 断 AirPods：1 秒内声音换过去，网页右上角「声音：…」跟着变，两首不错拍；`~/DJStudio/logs/` 里有「声音输出跟着系统换了」 |
| 网页播放头和声音对齐 | 状态帧带「听到的时刻」= 收到时刻 + 声卡报的输出延迟（PortAudio outputLatency + 一个 512 帧缓冲）；蓝牙耳机的实际延迟常比报的大 | 用 MacBook 扬声器看 kick 是否正好在播放头过拍线时响 |

| 四 Deck 的调度器（v5）在 Mac 上编得过、放得动 | 只在 Linux（gcc）上编过、测过；Mac 是 clang + CoreAudio，CI 的冒烟测试会跑一遍 v5 的四 Deck 示例 | App 的「体检」里看声音引擎的版本；`djstudio demo5` 放一遍示例谱，四台 Deck 的脉冲听起来是一下不是四下 |
| 四路 MP3 同时放 + 8 个发送效果 + 处理组，一个音频块（512 帧 = 11.6 ms）里算得完，一小时不掉音 | Linux 测试机上平均占预算的 13%；但那台机器（共享虚拟机、没有实时线程）60 分钟里有 36 块被打断，不能说明 Mac 上有没有欠载（docs/V5_G0.md「60 分钟」） | 在 Mac 上跑 `python packaging/macos/smoke_v5.py <引擎> --long 3600`，看「超过预算 N 块」是不是 0；演出时听有没有爆音 / 掉音 |
| 四 Deck 演出时读盘一直跟得上（没有哪台 Deck 断一小下） | Linux 上不出声、占满 CPU 时连着补块会掉块，补块之间让 150 µs 以后 0 次；Mac 构建机上有一次四个脉冲少了一个，判断是同一个原因，没法在构建机上直接证实。接着真声卡时是一次回调一块（和 Mixxx 自己一样），这条路没有在真机上量过 | 四 Deck 演出页上方有没有出现「读盘没跟上 N 次」（正常不出现；数到的是下限）；音乐放在慢的外接盘 / 网盘上时尤其要看 |
| 四 Deck 的演出画面（波形、调音台、EQ 曲线）在 Mac 的浏览器里显示正常、不卡，拖旋钮 / 推子能接管 | 只在 Linux 上的无界面 Chromium 里看过、点过（1440 宽时每帧 16.7 ms，四条滚动波形 + 总览 + 曲线每帧重画）；Safari 没试过；演示用的合成素材波形几乎只有蓝色，真曲子的蓝 / 绿 / 白三层没在这个画面上看过 | `demo5` 或自己的谱开始演出：波形滚得顺不顺；拖 CH1 的 LOW，看它变成橙色的「手动」、下面出现「回谱」；点波形，气泡问从哪一小节放 |
| 用到分频（Trans / Roll 选了频段）的谱，整体比不用的晚 6 ms（总输出也分频时 12 ms），画面的播放头已经算进去 | 引擎报的 `latency`（帧）；声卡自己的输出延迟另算（CoreAudio 报的那个数没在真机上核对过） | 看播放头压不压在听到的 kick 上；差得明显就把差多少毫秒告诉我们 |
